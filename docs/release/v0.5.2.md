# jsonx-lib v0.5.2 - Reader Fixes

**A fix release for the readers.** v0.5.2 budgets a stream of documents
per document instead of over the stream's whole life, gives the buffer
behind the stream reader's whole-value calls a bound of its own, makes the
whole-value calls refuse input after a single document, and makes
`find_pointer` under `DuplicateKeys::Last` take the member `parse` keeps.
Typed-decode error messages are now safe to write to a log. The writers'
output is unchanged.

## What is jsonx-lib?

The JSON layer of the owner's portfolio, with no dependencies. Its consumers
are rpc-io (JSON-RPC for LSP, DAP, and MCP), lsp-lang, LexerSketch's
emitters, and metrics-lib's JSON and OTLP/JSON exporters. It owns JSON
text: reading, writing, escaping, and your types, through explicit impls.

## What's new in 0.5.2

### A stream of documents is budgeted per document

`StreamReader::documents()` reads NDJSON, JSON Lines, or concatenated JSON
as it arrives. In 0.5.1, `Limits::max_input_bytes` counted every byte fed
over the reader's whole life, so under the defaults a long-lived connection
(a log feed, an event stream, a JSON-RPC pipe) was refused with
`InputTooLarge` after 64 MiB however small each document was. The budget now
applies to each document: the bytes fed since the current document began,
or, between documents, since the last one ended.

```rust
use jsonx_lib::{Limits, Parser, Step};

// A budget of 64 bytes per document, and 27 000 bytes fed in all.
let mut r = Parser::new().limits(Limits::new().with_max_input_bytes(64)).stream_reader().documents();
let mut docs = 0;
for _ in 0..1000 {
    r.feed(b"{\"id\": 12345, \"ok\": true}\n")?;
    while let Step::Ready(Some(_)) = r.read_value()? {
        docs += 1;
    }
}
assert_eq!(docs, 1000);
# Ok::<(), jsonx_lib::Error>(())
```

Outside documents mode the budget still bounds all the input, as it does
for a complete document. A `Reader` over a complete text in documents mode
has its whole input already and applies the budget to all of it.

### A bound on what a whole-value call holds

`next_event` reads in constant memory: one token and one chunk. The
whole-value calls (`read_raw`, `read_value`, `decode`) cannot: each keeps
its value's text, whitespace included, in the buffer until the value ends.
In 0.5.1 nothing but `max_input_bytes` bounded that buffer, so a stream
that raised `max_input_bytes` to stay open could be made to hold one value
of `[` followed by spaces without limit.

The new `Limits::max_value_bytes` (default 64 MiB, the same as the default
input budget) bounds it: a `feed` that would take the value a pending
whole-value call is reading past it is refused with `InputTooLarge` at the
first byte over the budget.

```rust
use jsonx_lib::{ErrorKind, Limits, Parser, Step};

let limits = Limits::new().with_max_input_bytes(usize::MAX).with_max_value_bytes(8);
let mut r = Parser::new().limits(limits).stream_reader();
r.feed(b"[1, ")?;
assert_eq!(r.read_value()?, Step::NeedInput);
let err = r.feed(b"2, 3, 4]").unwrap_err();
assert_eq!((err.kind(), err.offset()), (ErrorKind::InputTooLarge, 8));
# Ok::<(), jsonx_lib::Error>(())
```

`Limits` is `#[non_exhaustive]`, so the new field is not a breaking change.

### Input after a single document

`read_raw` and `read_value` on `Reader`, and `read_raw`, `read_value`, and
`decode` on `StreamReader`, answer "no value comes next" when the document
has ended. In 0.5.1 they gave that answer whatever followed the document,
so a loop that read until it accepted `7 8` or `{"a":1}}`, which `parse` and
`from_str` refuse. They now report `ErrorKind::TrailingCharacters` at the
first byte after the document that is not whitespace, as `next_event` and
`Reader::finish` do. A stream reader that has seen only whitespace after
the document answers as `next_event` does there: `NeedInput` until the
input has ended, then `Ready(None)`. Documents mode, where another document
may follow, is unchanged.

`StreamReader` also gains `finish`, which reads the rest of the input and
answers `Ready(())` once the input has ended with nothing but whitespace
after the document, `NeedInput` before that, or the first error: one call
to check that the input held exactly one valid document, wherever the
whole-value calls stopped.

```rust
use jsonx_lib::{ErrorKind, Step, StreamReader};

let mut r = StreamReader::new();
r.feed(br#"{"id": 1} "#)?;
assert!(r.read_value()?.is_ready());
assert_eq!(r.finish()?, Step::NeedInput); // more may follow
r.end_input();
assert_eq!(r.finish()?, Step::Ready(()));

let mut r = StreamReader::new();
r.feed(b"7 8")?;
assert!(r.read_value()?.is_ready());
assert_eq!(r.read_value().unwrap_err().kind(), ErrorKind::TrailingCharacters);
# Ok::<(), jsonx_lib::Error>(())
```

### `find_pointer` under `DuplicateKeys::Last`

Under the default `DuplicateKeys::Error`, every reading path refuses a
repeated key. Under `Last`, `parse` and typed reads keep an object's last
member with a key, but `Reader::find_pointer` took the first, so a router
that checked `/role` with `find_pointer` and acted on `parse` could see two
different values in one document. `find_pointer` now takes the last member
under `Last`: it reads each object on the way to its end, and leaves the
reader past the value it started on. Errors anywhere in those objects are
reported. `First` and `KeepAll` behave as before.

```rust
use jsonx_lib::{DuplicateKeys, Parser};

let last = Parser::new().duplicate_keys(DuplicateKeys::Last);
let doc = r#"{"role": "user", "role": "admin"}"#;
assert_eq!(last.parse(doc)?["role"], "admin");
assert_eq!(last.reader(doc).find_pointer("/role")?, Some(r#""admin""#));
# Ok::<(), jsonx_lib::Error>(())
```

### Error messages safe to log

A `DecodeError` names where in the document it happened, with the keys on
the way. Those keys come from the input, and `Display` printed them as they
were: a key holding a newline could add a forged line to a log, and a key of
16 MiB (the default string budget) made a message of 16 MiB. `Display` now
writes control characters, line and paragraph separators, and
bidirectional formatting characters as Rust escapes (`\u{a}` for a
newline), doubles backslashes, and cuts each key at 64 characters, ending
it with `...`. A message is one line, and its length is bounded by the
path's depth. `path()` and `pointer()` still give every key exactly.

### Documentation

- `to_string_pretty`: indentation grows with the square of the nesting
  depth. Under the default limits a parsed value is at most 128 levels
  deep; a value parsed with `Limits::unlimited()` or built in code may be
  too deep for its pretty text to fit in memory.
- `Format`, `ValueWriter::raw`, and `RawValue`: the plain formats copy raw
  text as it is, U+2028 and U+2029 inside its strings included (valid JSON;
  every string the writers make has them escaped). `html_safe` escapes them
  in raw text too, for output pasted into JavaScript source.
- `Object::insert` and `Object::entry` find the member by a linear scan, so
  building a large object with `insert` is quadratic; `push` and `collect`
  append without the scan.
- README: the typed-decoding comparison now reads as the time ratio it is:
  decoding a small request takes 2.3 to 2.6 times as long as `serde_json`'s
  derive.

## Compatibility

No public item was removed or changed in signature; `Limits::max_value_bytes`,
`Limits::with_max_value_bytes`, and `StreamReader::finish` are new. Three
behaviours change, each to agree with the rest of the crate:

- the whole-value calls return `TrailingCharacters` where they returned
  `None` for a single document followed by more than whitespace;
- `find_pointer` under `DuplicateKeys::Last` returns the last member and
  reads further;
- a stream reader in documents mode accepts more input in total, and
  reports a document over its budget at that document's limit.

## Security

The input budget now bounds each document of a stream and the value budget
each buffered value, so a long-lived stream needs no raised input budget
and a whole-value call cannot be made to buffer without limit. Input after a
single document is refused by every reading call, as by `parse`. Under
`DuplicateKeys::Last`, pointer lookups and the tree agree on which member a
repeated key means. Error messages no longer carry raw control characters
or unbounded keys from the input. The default policy (`DuplicateKeys::Error`)
and every other budget are unchanged.
